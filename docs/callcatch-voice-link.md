# CallCatch <-> CallCatch Voice link

Both add-ons already have the options. This doc and `voicemail/tools/wire_voice_link.py` make the pairing repeatable without anyone typing or seeing a secret.

| CallCatch Voice (source) | CallCatch (copy) | Used for |
|---|---|---|
| `ha_webhook_token` | `ingest_token` | Voice -> `POST /api/ingest` bearer |
| `trust_api_token` | `voice_trust_token` | CallCatch Numbers page -> Voice `/api/trust*` (allow/block list) |
| add-on hostname | `voice_trust_url` = `http://<hostname>:8787` | Supervisor-network only (no dots accepted) |

Rules: values are copied from Voice, never generated by the tool, never printed (report says only `match`/`differs`/`voice blank`). Nothing in git, chat, logs or `/config/www`.

## Apply (needs MA PASS + CoS/Bryson GO)
1. Backup.
2. If a Voice secret is blank, set it in the Voice Configuration tab (password field) and restart Voice.
3. In an add-on shell with `SUPERVISOR_TOKEN`: `python3 wire_voice_link.py` (dry run), then `--apply`.
4. Restart CallCatch. Verify `/api/diag` shows `ingest_configured: true`, the Numbers page lists allow/block entries, and Voice `/api/health` shows `trust_api_configured: true`.
5. Voice `ha_webhook_transcript` may then point at CallCatch `/api/ingest` instead of the legacy HA webhook route (separate change).

Rollback: blank the three CallCatch options and restart; calls keep arriving via the legacy route. `input_boolean.work_forward_dry_run` is untouched.
